# 小组协作流程

本文档说明三名成员每天怎么协作、组长怎么推进、任务怎么验收。

---

## 一、组长的核心职责

赵启行为本项目组长。组长不是负责做最多代码的人，而是负责让项目不散、不虚、不失控。

组长每天要盯住五件事：

1. 当前任务是否围绕 C0-C4 主线。
2. 每个人是否有明确交付物。
3. 数据、代码、日志、结果是否放在正确目录。
4. 结论是否能被测试集和指标验证。
5. 是否出现范围过大、进度失控或单人压力过大的情况。

---

## 二、每日同步

每天建议 10-15 分钟，不开长会。

每个人按模板回答：

```text
昨天完成了什么：
产出文件在哪里：
今天准备做什么：
当前卡点：
需要谁协助：
```

组长只做三件事：

1. 判断任务是否偏离主线。
2. 判断产出是否可检查。
3. 决定是否需要调整分工。

---

## 三、每周验收

每周至少做一次 60 分钟复盘。

必须检查：

| 检查项 | 说明 |
| :--- | :--- |
| 环境 | 新成员或另一台电脑能否 `uv sync` 后运行 |
| 数据 | 测试集是否增加，参考答案是否可判定 |
| 代码 | 是否有可运行脚本 |
| 日志 | 是否保存运行过程 |
| 结果 | 是否有结果表或案例 |
| 报告 | 本周工作是否能写进报告 |

---

## 四、任务状态

所有任务建议使用以下状态：

```text
未开始 / 进行中 / 待验收 / 已完成 / 有风险
```

不要使用“差不多”“快好了”这类状态。每个任务必须能看到产出文件。

---

## 五、阶段验收标准

| 阶段 | 验收标准 |
| :--- | :--- |
| 环境 | 三个人都能运行 `uv run python --version` |
| 数据集 | 至少 20 条首批测试题，每题有参考答案和证据 |
| C0 | 能检索、回答、输出引用和日志 |
| C1 | 能记录原问题和改写问题，并比较 C0/C1 |
| C2 | 能输出混合检索和 rerank 结果 |
| 工具 | 四类工具都能单独运行并保存日志 |
| C3 | 能展示任务规划、多轮检索和 self-check |
| C4 | 能展示工具选择、工具调用和工具结果验证 |
| 评测 | 有 C0-C4 主结果表和至少 3 个消融结果 |
| Demo | 能展示完整 Agentic RAG 链路 |
| 报告 | 能说明问题、方法、实验、结果、边界 |

## 六、冲突处理

### 1. 代码冲突

处理原则：

1. 不要直接删除别人的代码。
2. 先看冲突文件内容。
3. 找对应负责人确认。
4. 合并后必须运行相关脚本。

### 2. 任务冲突

如果两个人同时改同一文件，优先按模块分开：

| 文件类型 | 推荐负责人 |
| :--- | :--- |
| `data/testset/*` | B |
| `src/*` | C |
| `prompts/*` | A |
| `configs/*` | A/C |
| `docs/*` | A 主导，全员补充 |

### 3. 进度冲突

如果时间不够，删减顺序：

1. C4-Adaptive 选做内容。
2. 实时网页搜索。
3. 完整 Dify + RAGFlow 双系统对比，只保留一个。
4. 复杂图表。

不能删：

1. C0-C4 主线。
2. 测试集。
3. 核心消融。
4. 日志。
5. 失败案例。
