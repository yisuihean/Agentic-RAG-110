# 小组三人分工

本文档记录三名成员的固定角色、主要职责、近期交付物和协作边界。分工可以调整，但调整后必须更新本文档。

---

## 一、总体分工

| 角色 | 成员 | 主要方向 | 核心交付物 |
| :--- | :--- | :--- | :--- |
| A 方法与统筹负责人 | 赵启行，组长 | 研究主线、C0-C4 设计、Prompt、消融、报告和 PPT | 实验配置说明、Prompt、消融分析、报告主线 |
| B 数据与评测负责人 | 唐宁 | 知识库、测试集、参考答案、Benchmark、人工评分、失败案例 | `questions.csv`、`references.csv`、评分表、失败案例 |
| C 工程与 Demo 负责人 | 李金航 | 环境、代码、检索、工具、日志、Demo、C5 横向参考 | 可运行代码、日志、结果表、Demo |

---

## 二、成员 A：赵启行，方法与统筹负责人，组长

主要职责：

- 把握项目定位：不是产品型学习助手，而是 Agentic RAG 技术增强与评测。
- 设计 C0-C4 对比配置。
- 设计 query rewrite、task planning、self-check 的 Prompt。
- 设计核心消融实验。
- 统筹结题报告和答辩 PPT 主线。
- 每周检查项目是否偏离主线。

近期交付物：

- [ ] 明确 C0-C4 配置差异。
- [ ] 写出实验假设和五类指标。
- [ ] 编写第一版 Prompt 草稿。
- [ ] 设计至少三个核心消融：no-rewrite、no-self-check、no-tool。

协作边界：

- 和唐宁对齐测试题是否能验证方法。
- 和李金航对齐配置是否能被代码实现。

---

## 三、成员 B：唐宁，数据与评测负责人

主要职责：

- 收集和整理知识库材料。
- 建立 `documents.csv`。
- 编写自建测试集。
- 标注参考答案、证据和所需工具。
- 筛选 10-15 条公共 Benchmark 参考子集。
- 进行人工评分和失败案例整理。

近期交付物：

- [ ] 收集第一批知识库材料。
- [ ] 编写首批 20 条测试任务。
- [ ] 为每题标注参考答案和证据。
- [ ] 建立评分规则草稿。

协作边界：

- 不根据系统输出随意修改测试集。
- 正式实验前冻结测试集。
- 与赵启行一起确认题目是否服务研究问题。
- 与李金航一起确认数据格式是否能被程序读取。

---

## 四、成员 C：李金航，工程与 Demo 负责人

主要职责：

- 维护 Python 和 uv 环境。
- 实现文档解析、chunk、检索、rerank。
- 实现四类工具：文件读取、代码执行、计算器、表格分析。
- 实现 C3/C4 Agentic RAG 流程。
- 保存运行日志和结果表。
- 准备 Gradio Demo。
- 完成 Dify 或 RAGFlow 横向参考。

近期交付物：

- [ ] 确认 uv 环境可运行。
- [ ] 跑通最小 Python 脚本。
- [ ] 准备 C0 文档解析和检索代码。
- [ ] 设计日志字段。

协作边界：

- 不把 API Key 写进代码。
- 不写死个人电脑路径。
- 新增依赖必须用 `uv add`，并提交 `pyproject.toml` 和 `uv.lock`。
- 代码输出必须保存到 `runs/`。
